## 共享规则（两轴都遵守）

### read-only 边界

不改代码、不改测试、不改 spec / plan / `task.md`，不改他人 review 报告，不 `git commit` / `git push`，不派 sub-sub-agent。

### 不信任 implementer 自述

`task.md`（过程记录 / 收尾报告）是 claim 不是证据。一切以 `git diff {diff_anchor}` 与代码/测试本身为准。implementer 的「理由」（YAGNI / 保持简单 / 故意如此 / mock 是临时的）不算 finding 降级依据。

### 零发现合法与 finding 边界

- clean review（0 finding）是有效输出；**禁止凑数**。
- 范围内问题进 finding 表；范围外问题仅在结论段提示，**不进** finding 表。

### Pre-Report Gate（每条 finding 报前自问）

任一「否」即降级或丢弃：

1. 能否引精确 `file:line` 或测试名？
2. 能否描述具体失败场景（输入 / 状态 / 坏结果）？
3. 是否读了周边上下文？
4. 严重度是否可辩护？

### 重审追加

Round N（N≥2）在对应报告文件末尾追加 `## Round N (YYYY-MM-DD HH:MM UTC+8)` 小节，只写本轮新发现和前轮 finding 复核结论，不覆盖历史。`finding_id` 跨轮全局续编。默认轮次上限见 `AGENTS.md` `max_review_round`（当前 4）。

### 撤回配合

若对某 finding 举证争议，你可在报告末尾追加撤回记录（`finding_id` + 撤回理由）。撤回后该 finding 不再强制改代码。


### 系统性缺口去重

发现跨 task 的测试基础设施、公共代码、环境或工具链缺口时，先只读运行 `scripts/task.py list`，必要时 `scripts/task.py show <tid>` 查找等价 follow-up。**仅允许** `list` / `show`（只读）；禁止 `add` / `start` / `finish` / `block` 等写命令。已有 task 时在结论引用 tid，不重复报告同一 finding；当前 diff 扩大问题或缺口直接影响当前正确性、安全、协议兼容、测试可信度时，仍报告本次新增影响。

reviewer 只建议 follow-up 标题、slug 和阻断性。

### verdict 判定（仅本报告）

`critical` / `important` 为 blocking finding；`minor` 非阻断，但仍须由 implementer 写入 `task.md` 处置表。

- **职责边界**：你只写 finding 与本报告 `verdict`。`已修` / `遗留` / `撤回` 由 implementer 在 `task.md` 处置表填写；task 是否 `blocked` 由 `AGENTS.md`「blocked」与 `.agents/skills/tasks-run/SKILL.md`「Step 6：处置」决定，不是你的 verdict 字段。
- **PASS**：以 `git diff` 与代码/测试为准，当前无未解决的 critical / important（可有 minor）。
- **FAIL**：仍存在未解决的 critical / important。
- **Round N（N≥2）**：追加新 `## Round N` 小节并给**本轮** verdict（脚本取最后一条 `verdict`）。前轮 blocker 须用 diff/代码核实是否已消除或已按撤回流程作废，**不**采信处置表自称「已修」。前轮 blocker 仍在或本轮有新 blocker → FAIL；否则 PASS。
- **禁止**在同一 round 内因 implementer 临时修复而覆盖或追加「复核翻 PASS」；修完代码后须走完整下一轮双审（`.agents/skills/tasks-run/SKILL.md` Step 3→5）。

权威流程见 `.agents/skills/tasks-run/SKILL.md`「Step 6：处置」与 `AGENTS.md`「blocked」。

## 严重度三级（完整定义）

严重度表示优先级。所有 finding 须在 adoption 阶段处置（已修 / 遗留 / 撤回）；只有 critical / important 阻断。

### critical

- **实现轴**：bug / 安全 / 数据丢失 / broken functionality
- **测试轴**：测了假行为致 AC 看似覆盖但实际未验证；删除关键 AC 的测试；mock 掉被测逻辑本身

### important

本 task 在修复前不可信，例如：

- **实现轴**：verbatim 重复、swallowed errors、spec AC 缺失实现、违反 spec 不变量
- **测试轴**：恒真断言、弱化断言、删 expect、`.skip`、mock 误用、AC 缺测试、红灯未归因
- 危险模式扫描命中项（见测试轴 prompt）**最低 important**，不得标 minor

### minor

风格、覆盖可更广、命名优化、注释补充、文件膨胀、测试结构清理。
