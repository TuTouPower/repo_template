# 决策记录（ADR）

只记录已经确认、影响后续工作的非显然决策。追加新条目，不重写历史；决策被替代时，新条目通过“替代”字段引用旧编号。

每条结构：`## NNN 标题（YYYY-MM-DD）`，下接 `- 背景` / `- 选项` / `- 结论` / `- 替代` 四项；替代填旧编号，无则写「无」。

## 001 冲突阻塞收紧为 dep-ready 优先，根除依赖×冲突调度死锁（2026-08-07）

- 背景：backlog 间冲突曾按「序号小者优先」无条件阻塞——对端自身仍被依赖阻塞、根本跑不起来时也凭序号压人。当依赖方向与序号方向相反（前置序号反而更大），依赖规则与冲突规则对同一对 task 给出相反的先后结论，形成等待环；可跑集静默归零且无法自行恢复。此规则下甚至存在三条边两两合法（无冗余对）的多节点等待环，单靠写时冗余校验防不全。
- 选项：a) 保留规则，写时拒冗余边 + 调度时检测等待环报错；b) 收紧冲突阻塞语义——对端非 dep-ready 不阻塞；c) 冲突 tie-break 从序号改为依赖拓扑序。
- 结论：b 为主，a 的 edit 冗余校验保留作数据卫生。dep-ready 规则下可证明等待环退化为纯 depends_on 环（环内最小序号节点未被依赖阻塞则无人能以冲突压它、被依赖阻塞则其入边只能是依赖边，归纳得全环皆依赖边），已由既有 depends_on 环检测覆盖，原等待图死锁检测与 edit 前后对比门禁随之移除。选项 c 改动语义面太大，不取。
- 替代：无
