# 待办总账（未做未修）

项目里「已知、还欠着」的事只在本文件登记：未修 bug 与遗留待办各占一节，字段各管各的。

- 只留**未闭环**条目；闭环后整条迁入 `docs/archive/pending.md` 对应节。
- bug 编号 `bNNN`，遗留编号 `fNNN`，两套独立递增，不复用。
- 立即修完的 bug 走 task 流程即可，不必先登记。
- 闭环由 `tasks-run` 收尾完成（写 `修复：tXXX` / `处理：tXXX` 后整条迁 archive）；漏迁由 `repo-hygiene` 补迁。

## 未修 bug

结构：`### bNNN 简述（YYYY-MM-DD 发现）`，下接 `- 现象` / `- 影响` / `- 修复`。未闭环写「未修」。

- 现象：发生什么预期外行为
- 影响：受影响的功能和范围
- 修复：未修

## 遗留待办

该做未做的需求、review 遗留 finding、技术债都登记在此。`pending-to-task` 从这里捞并建 task。

已验证的技术发现不属于待办，写 `docs/findings.md`。

结构：`### fNNN 简述（YYYY-MM-DD 记录）`，下接 `- 来源` / `- 内容` / `- 处理`。未闭环写「未开 task」。

`- 来源` 写清出处：finding_id、原 tid、用户提出，或技术债自查。
