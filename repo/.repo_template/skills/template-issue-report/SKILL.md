# template-issue-report

在**消费项目**（从模板仓复制出的仓库）里，把发现的模板仓问题记成一份交接报告，交给模板仓 agent 后续研究处理。

**分工**：消费仓 agent 是需求方，只描述「遇到了什么、期望什么」；模板仓 agent 是实现方，负责读源码、定位根因、定方案。本 skill 的目的就是守住这条线——消费侧不越界去诊断，只把观察和需求写清楚、写详细。

**本 skill 在模板仓本体（工厂仓 / `repo/`）无效**——那是实现方，不是需求方。

## 触发场景

- 模板仓的工具链、skill、hooks、模板文件在消费仓里报错、行为不符预期、输出错误。
- 模板仓的工作流、目录权责、状态机、约定与本项目需求冲突，或「按模板走不通 / 缺能力」。
- 发现模板仓某部分疑似 bug，但无法或不该在消费侧定位根因。

遇到上述情况，**不静默绕过、不就地改模板仓产物、不自行修复**——先记报告。

## 硬边界（核心）

- **不读模板仓实现**：禁止打开 `.repo_template/scripts/*.py`、`.repo_template/hooks/*.py` 等实现源码去定位根因、猜测机制。定位根因是模板仓 agent 的事。
- **可读对外契约**：可以读仓根 `AGENTS.md`、`.repo_template/docs/`（`usage.md` / `architecture.md`）、各 `SKILL.md` 等「说明书」，以及消费仓自己的业务代码、文档、git 状态——用来判断「现象 vs 期望」的差距。可以运行模板工具链命令观察输出（`task.py --help`、跑某命令看报错原文），但不拆实现。
- **不给建议**：不写「根因是 X」「应该改成 Y」「建议 Z」。报告里只到「期望行为」为止。
- **要详细**：现象必须落到可复现、可验证的具体事实——具体命令、报错原文、具体路径、具体输入输出。禁止「好像有问题」「不太对」「偶尔出错」这类模糊表述；不确定就写「不确定」，别用模糊词掩盖。

## 步骤

1. **确认现象**。复现或回顾触发过程，收集：

    - 触发命令 / 操作（原样）。
    - 实际结果（报错原文、错误输出、行为结果，原样粘贴，不转述）。
    - 期望结果（从需求角度，模板「应该」怎样）。
    - 复现只用只读命令，或写入 `.scratch/` 隔离；不为收集现象改动消费仓生产树。

2. **判断归属**。确认问题来自模板仓而非消费仓自身：

    - 涉及 `.repo_template/` 分发的工具链 / skill / hooks / 模板文件 → 模板仓。
    - 是模板仓约定的工作流 / 目录权责 / 状态机与本项目冲突 → 模板仓。
    - 是消费仓自己的业务代码 / 项目特定配置 → 不记，走正常 task 流程。

3. **分类**。二选一：

    - `bug`：模板仓产物行为错误、报错、输出不符契约。
    - `需求`：模板仓设计 / 约定 / 能力缺口，或与项目需求冲突（非「坏」而是「不满足」）。

4. **写报告**。按下方模板写进 `.scratch/repo_template_issues/` 下新文件。文件名见「文件命名」。

5. **交接**。写完后向用户说明报告已生成及路径，由用户决定如何交给模板仓 agent（复制文件内容、或把路径/内容带给模板仓会话）。不 commit、不 push——`.scratch/` 已 gitignore，报告是交接件，不入库。

## 报告模板

照此结构填写，占位符 `{}` 全部替换或删除；无法填写的小节写「无」，不整节留空。

```markdown
# 模板仓问题报告

## 元信息
- 报告时间：{ISO 8601 带时区，如 2026-08-15T15:30:00+08:00}
- 消费仓：{仓库名 / 路径}
- 分类：{bug | 需求}
- 报告人视角：消费仓 agent（需求方，未定位根因、未给方案）

## 问题概述
{一句话：什么场景下，模板仓的什么，出了什么 / 缺什么}

## 现象
- 触发操作：{原样命令或操作}
- 实际结果：{报错原文 / 错误输出 / 行为结果，原样粘贴}
- 复现步骤：{消费侧可执行的步骤，逐步}
- 涉及模板仓组成部分：{如 .repo_template/scripts/task.py、某 skill、某 hook、某模板文件、某约定}

## 影响
{对当前工作 / 后续使用的影响：阻塞了什么、哪些场景会踩、严重程度}

## 期望行为
{从使用者角度，模板仓应提供什么行为 / 能力 / 约定；只描述期望，不写实现方案}

## 补充上下文
{有助于模板仓 agent 理解的消费侧背景：项目类型、已做的绕过尝试（仅现象，不涉及模板实现改动）、相关文档 / 配置}
```

## 文件命名

`.scratch/repo_template_issues/<YYYYMMDD>-<HHMMSS>.md`

- `<YYYYMMDD>-<HHMMSS>`：报告时间（本地时间，精确到秒，避免同分钟多报告冲突），如 `20260815-153000`。
- 一次报告一个文件；多个**无关**问题分开写多个文件，不要塞进一个文件。

## 完成

报告已写入 `.scratch/repo_template_issues/`，已向用户说明路径与交接方式。未读模板仓实现、未给方案、未 commit。
